Produce a production-style Redis 7.2 install from the tree at `/app` that has OpenSSL TLS compiled in (built-in, not `BUILD_TLS=module`) and uses jemalloc on Linux. Install with `PREFIX=/opt/redis72` so the binaries land in `/opt/redis72/bin`. Do not modify files under `/src`. You may change the `/app` build tree.

The install must provide `redis-server`, `redis-cli`, `redis-benchmark`, `redis-check-rdb`, `redis-check-aof`, and `redis-sentinel` under `/opt/redis72/bin` (Sentinel and the check tools may be the usual server hardlinks or copies). `ldd` on `redis-server` and `redis-cli` must show libssl. Starting `/opt/redis72/bin/redis-server` with `--tls-port 6379 --port 0` and no cert paths must fail as a TLS-enabled binary missing certificates, not as an unknown option. The server binary must be a jemalloc build: `INFO memory` from a short-lived plaintext instance on `127.0.0.1:6390` (then shut it down) must report `mem_allocator:jemalloc`.

Write `/results/build-report.json` as UTF-8 JSON with a trailing newline. Keys, in this order: `prefix` (string `/opt/redis72`), `tls` (string `yes`), `allocator` (string `jemalloc`), `server` (absolute path), `cli` (absolute path), `sentinel` (absolute path), `make_settings_tls` (the `BUILD_TLS` value stored in `/app/src/.make-settings` after the build), `make_settings_malloc` (the `MALLOC` value in that same file). Leave `/opt/redis72/bin/redis-server` in place; it does not need to keep running.
