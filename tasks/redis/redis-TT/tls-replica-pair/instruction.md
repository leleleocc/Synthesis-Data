Stand up a TLS-only Redis 7 replica pair for an internal cache that must not accept plaintext clients. Source is at `/app`; PEM material is at `/data/tls/ca.crt`, `/data/tls/redis.crt`, and `/data/tls/redis.key`. Build with TLS linked into the server and CLI (not as a loadable module). Do not modify files under `/src`.

The master must listen only on `127.0.0.1` TLS port `6379` (`port` 0) using those certs and `tls-auth-clients no`. The replica must listen only on `127.0.0.1` TLS port `6380` (`port` 0), replicate from the master over TLS (`tls-replication yes`), and serve reads. Turn the default user off on both instances. Create ACL user `app` with password `app-secret` and `+@all ~* &*`, and ACL user `repl` with password `repl-secret` and only the commands a replica needs to handshake and PSYNC (`+psync`, `+replconf`, and the small connection set those require), not `+@all`. AUTH as `repl` / `repl-secret` on the master must succeed, but that user must not be able to run `FLUSHALL`. The replica must authenticate to the master as `repl` (`masteruser` / `masterauth`). Protected mode may stay on because clients are local.

Leave both processes running. After the replica is online, a TLS `redis-cli` using `--cacert /data/tls/ca.crt` must AUTH as `app` / `app-secret` on 6379, SET `cache:probe` to `ok`, and then AUTH as `app` on 6380 and GET `cache:probe` as `ok`. AUTH as `default` must fail on both ports. A non-TLS connection to 6379 or 6380 must not speak the Redis protocol. Write `/results/repl.json` as UTF-8 JSON with a trailing newline: object keys `master_tls_port` (6379), `replica_tls_port` (6380), `role_master` (string from INFO replication role on the master), `role_replica` (string from INFO replication role on the replica), `master_link_status` (the replica's `master_link_status`), and `tls_build` (string `yes`).
