Onboard a SOC onto this Suricata tree by reproducing how the engine loads classification.config and how shipped rules refer to those classtypes. Stored classtypes must match `/app/src/util-classification-config.c` applied to `/app/etc/classification.config` (regex, comment/blank skipping, name normalization, duplicate handling, and classtype_id assignment). Usage counts come from every `*.rules` file under `/app/rules/`. Do not modify files under `/app`.

Write `/results/classtypes.json` as a UTF-8 JSON array. Each element is an object with keys in this order: `id` (integer classtype_id), `name` (normalized name string), `description` (string), `priority` (integer). Order the array by increasing `id`. Compact JSON: no space after `:` or `,`, two-space indentation is not used; the file is a single line plus a trailing newline. Include only classtypes that the loader would actually store.

Write `/results/classtype-usage.csv` with header `name,priority,rule_count,files` and one data row per stored classtype, sorted by `name` ascending (byte order). A rule line is a line in a `*.rules` file whose first non-whitespace character is not `#` and that is not all whitespace. `rule_count` is the number of those lines that contain `classtype:<name>` as a rule option for that normalized name. `files` is a semicolon-separated list of distinct basenames (for example `http-events.rules`) that contain at least one such option, sorted ascending; if none, `files` is empty (the row still has four comma-separated fields). LF newlines and a trailing newline. No quotes.

Also write `/results/unused.txt`: the stored classtype names that have `rule_count` 0, one name per line, sorted ascending, trailing newline. If none are unused, the file is empty (zero bytes). Create directory `/results/class-index/` containing one file `{id}.txt` per stored classtype, where `{id}` is the unpadded decimal classtype_id, whose contents are `{name}\n{priority}\n` with the normalized name and decimal priority.
