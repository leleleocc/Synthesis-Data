Reproduce a Sentinel failover for master name `cachemaster` on this host using `/app/sentinel.conf` as the template. Run a Redis master on `127.0.0.1:6379`, one replica on `127.0.0.1:6380`, and three Sentinels on `127.0.0.1:26379`, `127.0.0.1:26380`, and `127.0.0.1:26381` with quorum 2, `down-after-milliseconds` 2000, `failover-timeout` 10000, and `parallel-syncs` 1. Bind every process to `127.0.0.1`, keep `protected-mode yes` on Redis nodes, and put working directories under `/data/master`, `/data/replica`, `/data/sentinel1`, `/data/sentinel2`, and `/data/sentinel3`.

Trigger an automatic failover (the original 6379 instance must not remain master). When you stop, Sentinel `SENTINEL get-master-addr-by-name cachemaster` from port 26379 must report the new master host `127.0.0.1` and a port that is `6380` (or another local Redis you promoted), that process must `INFO replication` `role:master`, and at least one Sentinel process must still be listening. Leave the new master, the demoted node if it is alive, and all three Sentinels running.

Write `/results/sentinel_failover.env` as ASCII `KEY=value` lines with a trailing newline and keys in this order: `MASTER_NAME`, `OLD_MASTER_PORT`, `NEW_MASTER_PORT`, `NEW_MASTER_ROLE`, `SENTINEL_QUORUM`, `NUM_OTHER_SENTINELS`, `FAILOVER_STATE`. `MASTER_NAME` must be `cachemaster`, `OLD_MASTER_PORT` must be `6379`, `NEW_MASTER_PORT` must match `get-master-addr-by-name`, `NEW_MASTER_ROLE` must be `master`, `SENTINEL_QUORUM` must be `2`, `NUM_OTHER_SENTINELS` must be the integer from `SENTINEL master cachemaster` `num-other-sentinels`, and `FAILOVER_STATE` must be `ok`.
