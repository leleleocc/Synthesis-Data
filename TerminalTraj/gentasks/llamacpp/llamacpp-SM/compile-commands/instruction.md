Onboard a Linux gcc Release build of llama.cpp using the CMake presets in `/app/CMakePresets.json`, and leave a compilation database that tools can load from both the preset binary dir and `/app`.

Configure with the `x64-linux-gcc-release` preset so CMake writes `/app/build-x64-linux-gcc-release` (the preset `binaryDir`). That tree must contain `/app/build-x64-linux-gcc-release/build.ninja` and `/app/build-x64-linux-gcc-release/compile_commands.json`. `/app/compile_commands.json` must exist and contain the same UTF-8 JSON bytes as `/app/build-x64-linux-gcc-release/compile_commands.json`. The cache at `/app/build-x64-linux-gcc-release/CMakeCache.txt` must record generator Ninja, `CMAKE_BUILD_TYPE` Release, `CMAKE_EXPORT_COMPILE_COMMANDS` ON, and `GGML_CPU` ON. `CMAKE_C_COMPILER` and `CMAKE_CXX_COMPILER` must resolve to gcc and g++ (the image gcc-14/g++-14 toolchain). Do not turn on `GGML_CUDA`, `GGML_VULKAN`, or `GGML_SYCL`.

`ninja -C /app/build-x64-linux-gcc-release -t targets` must list both `ggml-cpu` and `llama`. Each `compile_commands.json` must be a UTF-8 JSON array of objects; every object has `directory` and `file` string keys and either `command` (string) or `arguments` (array of strings). At least one entry `file` path must end with `ggml-cpu.c` or `ggml-cpu.cpp`, and at least one must end with `/src/llama.cpp` or `src/llama.cpp`. Do not modify files under `/data`.
