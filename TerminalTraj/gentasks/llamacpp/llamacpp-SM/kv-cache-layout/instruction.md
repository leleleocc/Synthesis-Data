Integrate the llama.cpp KV cache sizing rules from `/app/src/llama-kv-cache.cpp` with ggml tensor byte sizes so a profiler can predict K/V layout for a given token-cell capacity without allocating a context. `kv_size` is the number of token slots (cells) in the cache, not bytes.

`/data/kv_cases.json` is a UTF-8 JSON array of case objects. Each object has keys `id` (string), `kv_size` (int), `n_seq_max` (int), `n_pad` (int), `unified` (boolean), `v_trans` (boolean), `is_mla` (boolean), `type_k` (string, ggml `type_name` such as `f16` or `q8_0`), `type_v` (string), and `layers` (array of objects with integer fields `n_embd_head_k`, `n_embd_head_v`, `n_head_kv` in that order). For each case compute the layout `llama_kv_cache` would use when `filter`, `reuse`, `share`, and `mem_other` are unset, `hparams.no_alloc` is false, and every layer `has_kv`. Use `n_stream = 1` when `unified` is true, else `n_stream = n_seq_max`. Per layer, `n_embd_k_gqa = n_embd_head_k * n_head_kv` and `n_embd_v_gqa = n_embd_head_v * n_head_kv`, except when `v_trans` is true and `n_embd_v_gqa` is not the same for every layer, in which case V is padded to the max `n_embd_v_gqa`. K is `ggml_new_tensor_3d(type_k, n_embd_k_gqa, kv_size, n_stream)`. V is omitted when `is_mla` is true; otherwise V is `ggml_new_tensor_3d(type_v, n_embd_v_gqa, kv_size, n_stream)`. Byte sizes follow contiguous `ggml_nbytes`: `ggml_row_size(type, ne0) * ne1 * ne2` with `ggml_row_size` from `/app/ggml/src/ggml.c` and the `type_traits` block sizes in ggml. `kv_size` is already a multiple of `n_pad`.

Write `/results/kv_layout.json` as UTF-8 JSON with a trailing newline: an array of objects in the same order as `/data/kv_cases.json`, each with keys in this order: `id` (string), `n_stream` (int), `n_layers` (int), `k_ne0` (int, first layer `n_embd_k_gqa`), `k_ne1` (int, `kv_size`), `k_ne2` (int, `n_stream`), `v_present` (boolean, false when `is_mla`), `v_ne0` (int, first layer allocated V width after the `v_trans` padding rule, or 0 if no V), `v_ne1` (int, `kv_size` or 0), `v_ne2` (int, `n_stream` or 0), `k_nbytes` (int, sum over layers), `v_nbytes` (int, sum over layers), `total_nbytes` (int, k_nbytes + v_nbytes). Also build `/results/kv_nbytes` with `g++` (no extra libraries). Usage: `/results/kv_nbytes <type> <ne0> <ne1> <ne2>` where `<type>` is a lowercase ggml type name such as `f16`, `f32`, or `q8_0`; print a single integer byte count and a newline; exit 2 on unknown type or when `ne0` is not divisible by the type block size. Do not modify files under `/data`.
