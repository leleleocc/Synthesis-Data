# 批次 SOP 复盘

当一批 task construction 全部结束，或调用方冻结批次截止点时，执行本流程。产出一份供人
选择的 SOP 变更报告；得到选择后，才修改构造 SOP。

复盘范围是任务质量与 target/solver 分差构造。运行故障只影响证据是否可用，不产生任务设计
结论。所有判断使用 programmatic evidence，并保持既有 R、reward、criterion weight 职责和
交付标准。

## 1. 清点证据

列出批次内每个任务，并为每个任务确定：最终 task、可读的 raw round、trial 有效性、round
与最终 task digest 的关系，以及纳入或排除复盘的原因。以 raw Harbor evidence 为事实源；
用 `resume.md` 定位修改和假设，只在因果仍不清楚时读取 trajectory。

不完整 round 或 digest 不匹配的 round 只能说明进度。agent-judge rubric 只作背景；分差结论
来自 programmatic criteria。

完成条件：批次中的每个任务都有一条证据清单；每个纳入任务都标明使用的 round、有效 trial
和 digest 关系；每个排除任务都有具体原因。

## 2. 建立逐任务证据链

对每个纳入任务，找到连贯修改前后的可比较 round，计算 target_mean、solver_mean、R 和主要
criterion delta 的变化，然后回答：

1. 哪次修改产生了可观察变化？
2. 变化来自真实能力要求，还是共同失败、权重移动、提示泄露或采样波动？
3. 题面、test 或 verifier 是否有明确缺陷及可运行反例？
4. 哪个判断被后续 round 推翻？
5. 哪个做法有效但尚未跨任务复现？

修改与采样无法对齐时，把结果记为现象，不建立因果。

完成条件：五个问题在每个纳入任务上都有答案；每项因果判断都引用任务 ID、修改前后 round
和对应 raw evidence；只有现象的条目明确标为无因果结论。

## 3. 合并跨任务候选

把相同机制合并成候选经验。每条候选都写成：在一个既有生命周期节点采取什么动作、观察
什么证据、避免什么误判。保留作用机制、适用边界、支持证据和反证；去掉任务领域、文件名、
固定权重和参考实现细节。同一任务的多个 round 只算一个任务证据。

完成条件：每条候选都有唯一生命周期节点、可执行动作、支持任务、反证检查和适用边界；批次
中的相反结果已全部计入。

## 4. 决定去向

每条候选只进入一个去向：

- **SOP 正文，明确错误：** 已有一个可运行反例，证明交付状态不可复现、直接契约矛盾、参考
  实现锁定或 verifier 失真。
- **SOP 正文，构造策略：** 至少两个不同任务独立复现，并且各自都有可比的修改前后 round。
- **技巧附录：** 一个任务中机制合理且有效，但尚未达到构造策略门槛。技巧只提供探索方向；
  每次使用仍从当前任务证据重新判断。
- **不沉淀：** 证据被反驳、依赖具体仓库形状、只有总分相关性、仅改变 target_mean 而没有解释
  分差来源，或依赖无效 round。

完成条件：每条候选都满足其去向的证据门槛；未达到门槛的候选已降为技巧或明确淘汰。

## 5. 写复盘报告

将报告写到调用方指定的位置；未指定时使用
`docs/reviews/YYYY-MM-DD-<batch>-sop-review.md`。报告必须包含证据清单、SOP 建议、技巧附录
候选和明确不沉淀的结论。

对每条 SOP 建议，给出生命周期节点、证据任务、作用机制、反证检查和最小替换措辞。先检查
现有 SOP；相同含义用替换或合并表达，保留一个事实源。机械有效性放第 2 步，采样可比性放
第 3 步，判据归因放第 4 步，分差构造放第 5 步，交接证据放第 6 步。

技巧少且不打断主流程时，可建议放在 SOP 末尾的非规范性附录；篇幅妨碍步骤扫描时，建议拆到
独立 reference 文件并从对应步骤设置触发指针。

完成条件：每个纳入任务都能从报告追溯到证据；每条 SOP 建议都能在一个位置完成修改；报告
没有改变 R、reward、权重职责或交付标准。提交报告供人选择，在选择前保持构造 SOP 不变。
